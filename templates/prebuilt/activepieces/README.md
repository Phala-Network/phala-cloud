# activepieces/activepieces on Phala Cloud

## Overview

Deploy [activepieces/activepieces](https://github.com/activepieces/activepieces) on Phala Cloud as a CPU-safe automation and AI workflow builder.

Activepieces is an open-source alternative to Zapier and Make for building scheduled jobs, webhook flows, integrations, AI agent workflows, and internal automations. This template uses the official Activepieces container image in a standalone Docker Compose file, but intentionally runs the simplified single-container runtime documented by upstream: PGLite for embedded PostgreSQL storage and the in-memory queue instead of the full PostgreSQL, Redis, and multi-worker production stack.

This is suitable for first-run evaluation and light single-instance use on `tdx.small` style resources. For production, multi-instance, or high-throughput deployments, upstream recommends the full Docker Compose architecture with external PostgreSQL, Redis, and separately scalable workers.

## Included services

- `activepieces`: Activepieces web UI, API server, worker, webhook receiver, embedded PGLite database, and in-memory queue.

The service listens on container port `80` and is published as host port `8080`.

## Required environment variables

Real secrets must be generated by the deployer and are not included in this template.

| Variable | Required | Example generator | Purpose |
| --- | --- | --- | --- |
| `AP_ENCRYPTION_KEY` | Yes | `openssl rand -hex 16` | Stable 32-character hexadecimal key used to encrypt saved connections and credentials. Keep it unchanged across redeploys. |
| `AP_JWT_SECRET` | Yes | `openssl rand -hex 32` | Stable random JWT signing secret. Keep it unchanged across redeploys so sessions and tokens remain valid. |

Optional variables:

| Variable | Default | Purpose |
| --- | --- | --- |
| `AP_FRONTEND_URL` | `https://${DSTACK_APP_DOMAIN}` on Phala, or `https://localhost:8080` when no Phala domain is present | Public base URL used for webhooks, redirects, and OAuth callbacks. Set this explicitly if your deployment has a custom domain. |
| `AP_TELEMETRY_ENABLED` | `false` | Enables or disables upstream telemetry. |
| `AP_CLOUD_AUTH_ENABLED` | `false` | Controls use of upstream-managed OAuth applications. Leave disabled unless you want Activepieces cloud OAuth behavior. |
| `AP_WORKER_CONCURRENCY` | `2` | Number of concurrent jobs handled by the built-in worker. Increase only after sizing CPU and memory. |
| `AP_DEFAULT_CONCURRENT_JOBS_LIMIT` | `2` | Default per-project concurrent run limit. |

The compose file also pins `AP_DB_TYPE=PGLITE`, `AP_REDIS_TYPE=MEMORY`, `AP_CONTAINER_TYPE=WORKER_AND_APP`, and `AP_FILE_STORAGE_LOCATION=DB` to keep the default deployment self-contained.

## Persistent data

The template creates named Docker volumes only:

- `activepieces_data`: mounted at `/root/.activepieces` for PGLite data and local Activepieces configuration.
- `activepieces_cache`: mounted at `/usr/src/app/cache` for Activepieces runtime cache data.

No host bind mounts are used.

## Deploy on Phala Cloud

1. Select the prebuilt `activepieces` template.
2. Generate and set `AP_ENCRYPTION_KEY` and `AP_JWT_SECRET`.
3. Optionally set `AP_FRONTEND_URL` if you already know the public custom domain. Otherwise the template derives it from `DSTACK_APP_DOMAIN` when Phala provides that value.
4. Deploy the template with the default resources for the first smoke test: 2 vCPU, 2 GB memory, and 20 GB disk.
5. Open `https://<your-app-domain>` and create the first Activepieces user.

For local Docker Compose validation from the parent monorepo worktree:

```bash
docker compose -f templates/prebuilt/activepieces/docker-compose.yml config
```

For local runtime testing, provide generated secrets before starting:

```bash
AP_ENCRYPTION_KEY=$(openssl rand -hex 16) \
AP_JWT_SECRET=$(openssl rand -hex 32) \
AP_FRONTEND_URL=http://localhost:8080 \
docker compose -f templates/prebuilt/activepieces/docker-compose.yml up
```

## Verify / smoke test

Use the Activepieces health endpoint:

```bash
curl -fsS https://<your-app-domain>/api/v1/health
```

Expected response after startup:

```json
{"status":"Healthy"}
```

For a local compose run, use:

```bash
curl -fsS http://localhost:8080/api/v1/health
```

The container healthcheck probes the same `/api/v1/health` path from inside the container.

## Security notes

- Required secrets are referenced from environment variables and are not embedded in the compose file or README.
- Keep `AP_ENCRYPTION_KEY` and `AP_JWT_SECRET` stable and private. Rotating them can invalidate stored credentials, sessions, and tokens.
- This template does not request GPU devices, privileged mode, host networking, host bind mounts, `env_file`, external build contexts, browser automation, or hosted provider credentials.
- PGLite and the in-memory queue are single-instance components. Do not scale this compose service horizontally.
- `AP_EXECUTION_MODE=UNSANDBOXED` matches the upstream self-hosted default, but it means user-authored flow code runs in the Activepieces process. Restrict access to trusted users and move to an upstream production architecture if you need stronger workload isolation.
- External app integrations, LLM providers, SMTP, S3, and OAuth applications can be configured after deployment, but their credentials are intentionally not included here.
